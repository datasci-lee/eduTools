# macOS 판서 앱 설계서

Oct 30, 2026 · @이경환

> 2026-10-28 결정: 최소 지원 **macOS 26**. 빌드는 Command Line Tools `swiftc`(Xcode 없음). 전역 단축키는 Carbon `RegisterEventHotKey` 직접 사용(외부 라이브러리 없음).

## 개요

수업 중 어떤 앱 위에서든 바로 판서하고, 화면을 확대하고, 수업·쉬는 시간을 관리하는 macOS 메뉴바 앱입니다. **Swift + AppKit** 네이티브로 개발하고, 설정 화면만 SwiftUI로 만듭니다.

| 항목 | 결정 |
| --- | --- |
| 대상 사용자 | 강의·수업을 진행하는 강사 (마우스, 트랙패드, 펜 태블릿 사용) |
| 플랫폼 | macOS 26 이상. 이후 **Windows 11 이상**으로 확장(Rust 로 별도 구현, Windows PC 에서 개발 — [`windows-plan.md`](windows-plan.md)) |
| 언어/프레임워크 | Swift, AppKit, SwiftUI(설정), ScreenCaptureKit, Core Animation |
| 앱 형태 | 메뉴바 상주 앱 (Dock 아이콘 없음) + 떠 있는 도구 팔레트 |
| 배포 | Developer ID 서명·공증 후 직접 배포 (App Store는 이후 검토) |

네이티브를 택한 이유: 투명 오버레이, 클릭 통과, 전체화면 앱 위 표시, 실시간 화면 확대, 펜 압력을 지연 없이 다룰 수 있는 건 AppKit뿐입니다. Electron·Flutter는 줌과 오버레이 제어에서 한계가 있습니다.

## 핵심 기능

모든 도구는 **판서 모드**에서만 입력을 받고, 판서 모드를 끄면 클릭이 아래 앱으로 그대로 통과합니다. 판서 내용은 모드를 끄더라도 화면에 남게 할지 설정에서 고릅니다.

### 펜

- 색상 프리셋 6개(숫자키 1~6) + 사용자 지정 색
- 굵기 1~30pt, `[` `]` 키로 조절
- 선 스무딩(Catmull-Rom 곡선), 펜 태블릿 압력에 따라 굵기 변화. 유효 굵기 = 설정 굵기 × `(최소 비율 + (1 - 최소 비율) × pressure)`이며 최소 비율은 0.05~1(기본 0.2, 1이면 필압 미사용)
- Shift를 누른 채 그리면 직선(0·45·90도 스냅)

### 형광펜

- 반투명(기본 40%), 곱하기(multiply) 혼합으로 글자가 비쳐 보이게
- 한 획 안에서 겹쳐 칠해도 진해지지 않음
- 기본 굵기 18pt, 끝이 납작한 펜촉, Shift 시 수평 직선

### 레이저 포인터

- 빛나는 점 + 지나간 점을 이차 곡선으로 이은 꼬리가 설정 시간(0.1~10초) 뒤 서서히 사라짐
- 클릭 없이 마우스 이동만으로 표시, 색상·크기 설정 가능

### 지우개

지우개는 **범위(크기)**와 **지우는 방식**을 따로 설정합니다.

- 범위: 원형 커서, 지름 8~200px. `[` `]`(현재 도구 크기 키) 또는 지우개 모드에서 스크롤로 조절하고, 커서에 실제 범위가 원으로 표시됨
- 크기 프리셋 3개(소·중·대)를 팔레트에서 바로 선택

| 지우는 방식 | 동작 | 언제 쓰나 |
| --- | --- | --- |
| 부분 지우기 (기본) | 지우개 원이 지나간 부분만 지움. 획이 두 개로 갈라질 수 있음 | 글자 일부만 고칠 때 |
| 획 단위 지우기 | 원에 닿은 획을 통째로 지움 | 잘못 그은 선 하나를 빠르게 지울 때 |
| 영역 지우기 | 드래그로 사각형(또는 올가미)을 그리면 그 안의 획을 모두 지움 | 한 구역만 정리할 때 |

- 획 단위·영역 지우기에는 판정 기준 옵션: **조금이라도 닿으면** 지움 / **완전히 들어가야** 지움
- 대상 필터: 모두 / 펜만 / 형광펜만 (형광펜만 지우고 판서는 남길 수 있음)
- 지우기도 Undo로 되돌릴 수 있음

### 초기화·실행 취소

- 전체 지우기, 현재 모니터만 지우기
- 실행 취소/다시 실행 최소 100단계, 전체 지우기도 되돌리기 가능

### 화이트보드·블랙보드

- 화면을 흰색 또는 검은색(칠판 느낌의 진녹색 선택 가능) 배경으로 덮음
- 보드마다 판서 내용을 따로 저장해, 화면 판서·보드 사이를 오가도 내용이 유지됨
- 여러 페이지(← →로 넘김), 격자·줄 배경 옵션
- 블랙보드에서는 검은 펜을 자동으로 흰색으로 바꿔 표시

### 화면 줌

- **배율 조절**: 1.25배~8배. 줌 중 ⌘+스크롤 또는 `+` `-` 키로 0.25배씩 변경, 트랙패드 핀치도 지원
- 줌을 켤 때 시작 배율은 설정값(기본 2배) 또는 마지막 사용 배율
- 화면 한쪽에 현재 배율을 잠깐 표시(예: ×3.0)
- **라이브 줌**: 마우스를 따라 확대 영역이 부드럽게 이동. 따라가는 속도(부드러움) 설정 가능. 아래 앱의 영상·스크롤도 실시간 반영
- **정지 줌**: 현재 화면을 멈춘 채 확대. 이 상태에서 판서하면 확대된 화면 위에 글씨가 써짐
- 줌 중 화면 가장자리에서는 더 이상 이동하지 않게 고정

화면 캡처에는 커서를 포함하지 않고 앱이 줌 창 최상단에 벡터 화살표 포인터를 직접 그립니다. 라이브에서는 원본 포인터의 확대 표시 위치에 배율만큼, 정지에서는 실제 포인터 위치에 배율만큼, 미리보기에서는 실제 위치에 1배로 표시하며 세 상태 모두 시스템 커서를 숨깁니다. 포인터가 움직일 때마다 투명 커서를 다시 설정해 시스템 커서가 겹쳐 보이지 않게 합니다. 라이브↔정지 전환과 정지 상태 종료 때 실제 포인터를 옮겨 시각 위치를 보존하며, 아래 앱의 커서 종류를 알 수 없어 현재는 화살표 하나만 표시합니다. 캡처 프레임은 IOSurface를 줌 레이어에 직접 전달하고, IOSurface가 없는 예외 프레임만 경고 로그 뒤 CGImage로 변환합니다.

라이브 줌에서도 확대된 커서 끝에 바로 판서할 수 있으며, 판서는 화면 좌표에 저장되어 확대 위치가 바뀌어도 같은 자리에 남고 마우스를 따라 이동하지 않습니다. 획·도형·가리개·지우기·선택 조작·텍스트 입력 중에는 확대 위치와 배율을 잠그고, 상호작용이 끝나면 따라가기를 재개합니다.

줌 중 판서 모드가 켜져 있으면 미리보기가 아닌 라이브·정지 상태 모두 판서 단축키가 동작하며, 줌 전용 키를 먼저 처리합니다.

**마우스 따라가기 방식**: 라이브 줌에서 확대 영역이 마우스를 따라가는 방식을 세 가지 중에서 고릅니다. 기본값은 설정에서 정하고, 줌 중에는 `F` 키로 바꿉니다.

| 방식 | 동작 | 어울리는 상황 |
| --- | --- | --- |
| 항상 따라가기 | 마우스가 항상 확대 화면 가운데에 오도록 확대 영역이 계속 이동 | 화면 여기저기를 빠르게 훑어보며 보여줄 때 |
| 가장자리에서만 이동 (기본) | 마우스가 확대 화면 가장자리(안쪽 10%)에 닿을 때만 그 방향으로 밀려 이동. 가운데에서는 화면이 멈춰 있음 | 코드·문서를 가리키며 설명할 때. 화면이 덜 흔들려 학생이 어지럽지 않음 |
| 고정 | 마우스를 움직여도 확대 영역은 그대로. 위치는 `Space` 위치 미리보기로만 옮김 | 한 곳을 오래 보여줄 때 |

- 따라가는 속도(부드러움)는 세 방식에 공통으로 적용
- 방식을 바꾸면 화면 아래에 "따라가기: 가장자리"처럼 잠깐 표시
- **정지 줌에서는 항상 고정**: 판서 중에 화면이 펜을 따라 움직이면 글씨가 밀리므로, 정지 줌에서는 설정과 관계없이 확대 영역을 고정. 위치를 옮기려면 `Space` 위치 미리보기를 사용하고, 옮긴 뒤에는 새 위치의 화면으로 다시 멈춤. 이전 위치에 쓴 판서는 그 자리에 남아 있음
- **두 손가락 화면 이동 (Windows 터치 화면)**: 줌 중 손가락 두 개를 대고 끌면 손가락 아래 내용이 함께 끌려오듯 확대 영역이 이동(확대 화면 1px = 원본 1/배율 px, 원본 화면 가장자리에서 멈춤). 라이브·정지 모두 동작하고 판서 모드와 무관하며, 미리보기 중에는 쓰지 않음
  - 두 번째 손가락이 닿으면 첫 손가락이 긋던 획은 확정하지 않고 버리고, 모든 손가락을 뗄 때까지 터치는 판서로 넘기지 않음(한 손가락만 떼도 남은 손가락이 획을 긋지 않음)
  - 펜·마우스가 획을 긋는 중이거나 펜 사용 직후 1초(손바닥 인식 구간)에는 시작하지 않음 — 손바닥 두 점이 화면을 끌지 않게
  - 라이브 줌에서는 옮긴 뒤 커서가 그 자리에 있는 동안 따라가기를 멈춰, 옮긴 화면이 커서 쪽으로 되돌아가지 않음. 마우스·펜을 움직이면 평소처럼 따라가기 재개
  - 정지 줌에서는 멈춘 전체 화면 안에서 보는 위치만 옮김(새로 캡처하지 않음). 판서는 원본 좌표에 있어 그대로 따라감
  - macOS는 터치 화면이 없어 해당 없음(트랙패드 핀치·스크롤은 기존대로)

**확대 위치 미리보기**: 줌 상태에서 `Space`를 누르고 있는 동안 전체 화면으로 잠시 빠져나와, 지금 확대된 위치를 보여줍니다. 손을 떼면 확대 화면으로 돌아갑니다.

- 누르는 순간 0.15초 애니메이션으로 1배 전체 화면으로 축소(키 반복 입력은 무시)
- 확대되어 보이던 영역만 원래 밝기·색으로 표시하고 강조 테두리(2px)와 배율(예: ×3.0)을 붙임
- 나머지 영역은 회색 처리(채도 0, 밝기 낮춤)해 확대 위치가 한눈에 들어오게 함. 회색 농도는 설정에서 조절
- 키를 누른 채 마우스를 움직이면 밝은 사각형이 따라 움직이고, 스크롤하면 사각형 크기(=배율)가 바뀜. 키를 떼면 그 위치·배율로 다시 확대
- 누른 채 `Esc`를 누르면 이동을 취소하고 원래 위치로 복귀
- 정지 줌에서 한 판서도 미리보기 화면에 제 위치·크기로 표시
- 구현: 줌 엔진이 이미 전체 화면을 캡처하고 있으므로 표시 배율만 바꿈. 회색 처리는 Core Image(`CIColorControls`)를 확대 영역 바깥에만 적용. 키를 뗄 시점은 keyUp 이벤트로 감지(Windows는 `WM_KEYUP`)

## 부가 기능

| 기능 | 내용 |
| --- | --- |
| 도형 | 직선, 화살표(한쪽·양쪽), 사각형, 원. Shift로 정사각형·정원. 손그림은 0.5초 멈춰도 그리는 동안 모양을 유지하고, 그 상태에서 펜을 뗄 때만 인식된 도형으로 교체(켜기/끄기) |
| 텍스트 | 클릭한 위치에 글자 입력, 한글 IME 지원, 글꼴 크기·색상 |
| 선택·이동 | 올가미로 획을 선택해 이동·크기 변경·삭제 |
| 스포트라이트 | 마우스 주변 원만 밝게, 나머지는 어둡게. 원 크기는 스크롤로 조절 |
| 커서 강조 | 마우스 주변에 색 원 표시, 클릭 시 파문 효과(좌·우클릭 색 구분) |
| 키 입력 표시 | 누른 단축키를 화면 하단에 잠깐 표시 (예: ⌘C). 프로그램 시연에 유용 |
| 저장·내보내기 | 현재 화면+판서를 PNG로 저장, 보드 여러 페이지를 PDF 한 파일로 저장, 클립보드 복사 |
| 자동 보관 | 판서를 끄거나 지울 때 직전 내용을 날짜별 폴더에 자동 저장(옵션) |
| 멀티 모니터 | 모니터마다 독립된 판서층. 줌·보드는 마우스가 있는 모니터에 적용 |
| 도구 팔레트 | 원형이 기본이며 설정에서 가로형으로 전환. 원형은 중심·1~3링을 접고 펼치며 끌어서 이동하고, 현재 도구·색·굵기를 표시. `Tab`으로 숨김/표시 |
| 화면 가리개 | 사각형 가림막을 놓고 하나씩 걸어서 정답을 드러내기 |
| 화면 녹화 연동 | 판서층이 화면 녹화·화상회의 화면 공유에 그대로 나오도록 창 설정(숨길 도구 팔레트는 공유에서 제외) |
| 펜 태블릿 | Wacom 등 펜의 압력·지우개 끝 자동 인식, 우클릭 = 임시 지우개 · Pencil 더블탭 = 지우개 ↔ 이전 도구, iPad Sidecar + Apple Pencil 지원 |

## 원형 도구 팔레트

원형 팔레트는 바깥으로 갈수록 “무엇을 → 무엇으로 → 어떻게”를 고르는 Minimal Arc 구조이며 기본 팔레트입니다. 설정의 도구 탭에서 가로형으로 전환할 수 있습니다.
면은 블러나 색조 자동 전환 없이 RGB(20,23,31)의 어두운 단색을 반투명으로 그립니다. 기본 불투명도는 0.86, 설정 UI와 렌더 범위는 0.75~0.90이며 옛 설정 호환을 위한 저장 검증만 0.55~0.90을 허용합니다. 1링은 글자 없는 도넛, 2링은 도구 아이콘을 담은 부채꼴 캡슐, 3링은 안쪽 트랙과 바깥 노드이며 그룹·범주 이름은 화면에 표시하지 않습니다. 바깥 테두리·호버·활성 호와 밝은 아이콘으로 상태를 구분하고 비활성 내용에는 55%를 적용합니다. 중심·키캡·힌트도 같은 어두운 면을 쓰며 칸이 없는 영역은 완전히 투명합니다.
창은 그리는 영역보다 사방으로 `windowMargin`만큼 큽니다. 면 테두리와 포커스 링이 창 경계에서 잘리지 않게 하기 위한 여백입니다.

### 도구 속성 아이콘

원형 중심·2링 도구 칸·가로 팔레트 도구 버튼은 `assets/symbols/attr/manifest.json`의 레이어 규칙으로 현재 또는 도구별 마지막 설정을 합성합니다. 일반 아이콘 키와 단축키 표, 명령 실행 경로는 그대로 사용하며, 매니페스트나 레이어를 읽지 못하면 사유를 한 번 로그하고 일반 아이콘으로 돌아갑니다. 선택·화면 가리개처럼 매니페스트에 없는 도구와 1링·3링·도움말·메뉴바는 일반 아이콘을 유지합니다.

| manifest 도구 | 앱 도구 | 속성 입력 |
| --- | --- | --- |
| `tool.pen` | `.pen` | `perToolMemory.pen` 색·크기 |
| `tool.highlighter` | `.highlighter` | `perToolMemory.highlighter` 색·크기 |
| `tool.text` | `.text` | `perToolMemory.text` 색·글자 크기 |
| `tool.arrow` | `.arrow` | `perToolMemory.arrow` 색·크기, `arrowStyle`의 single/double |
| `tool.rect` | `.rectangle` | `perToolMemory.rectangle` 색·크기, 채움 없음 |
| `tool.circle` | `.ellipse` | `perToolMemory.ellipse` 색·크기, 채움 없음 |
| `tool.eraser` | `.eraser` | 지름, partial→brush·stroke→stroke·area rectangle/lasso→rect/lasso |
| `tool.laser` | `.laser` | `laserColor`, 꼬리 켬 |

두께 단계는 `1 + min(3, floor(4t))`, `t = clamp((size - lo) / (hi - lo), 0, 1)`로 계산하고 `hi == lo`이면 2단계로 둡니다. 범위는 3링 정본인 `RadialPaletteMetrics.writingWidths`·`highlighterWidths`·`textSizes`의 최솟값과 최댓값, 지우개는 설정의 `presetDiameters` 최솟값과 최댓값을 사용합니다.

`attr` 레이어와 바로 뒤 배경의 WCAG 상대휘도 명암비가 1.8 미만이면 `.fill`이 아닌 레이어를 0.5pt씩 사방으로 먼저 그려 1pt halo를 만듭니다. 밝은 배경은 검정 55%, 어두운 배경은 흰색 70%입니다. 원형 팔레트의 halo 배경 추정값은 선택 시 시스템 강조색, 그 밖은 고정 어두운 면 0.07입니다. 실제 면은 RGB(20,23,31)를 설정 불투명도 0.75...0.90으로 합성합니다. 저장 검증은 옛 설정 호환을 위해 0.55...0.90을 허용하며, 저장값이 0.55...0.74이면 다시 쓰지 않고 렌더에서 0.75로 올립니다. 가로 팔레트의 시스템 면은 선택 시 시스템 강조색, 그 밖은 시스템 모양에 따라 흰색 0.93 또는 0.18로 근사해 기존 동작을 유지합니다. 설정·호버·선택·통과 모드가 바뀌면 원형 아이콘을, 시스템 모양이 바뀌면 가로 팔레트 아이콘을 키+속성+렌더 상태 캐시 키로 다시 선택하거나 합성합니다.

## 멀티 모니터·iPad(Apple Pencil) 지원

iPad는 macOS **Sidecar**로 연결해 하나의 모니터처럼 다루고, Apple Pencil 입력은 펜 태블릿과 같은 경로로 받습니다. 따라서 별도 iPad 앱 없이 MVP에서 바로 지원할 수 있습니다.

저장·적용·자동 전환 규칙은 [화면 구성 프리셋](#화면-구성-프리셋)을 따릅니다.

### 사용 방식 3가지

| 방식 | 어떻게 보이나 | 장점 | 단점 |
| --- | --- | --- | --- |
| 미러링 | iPad가 프로젝터 화면과 같은 화면을 보여줌(macOS 기능) | 추가 구현 거의 없음. 펜으로 쓴 자리가 그대로 화면에 나오는 가장 직관적인 방식 | 화면 비율이 다르면 여백이 생김 |
| 확장 모니터 | iPad가 독립된 화면. 앱은 iPad에도 별도 오버레이를 띄움 | 강사 메모·자료를 iPad에 따로 둠 | 쓴 내용이 프로젝터에는 안 나옴 |
| **판서 패드** (권장) | iPad는 확장 모니터지만, 앱이 프로젝터 화면을 iPad에 실시간으로 비춰주고 iPad에 쓴 획을 프로젝터 화면 좌표로 옮겨 그림 | 교탁 어디서나 iPad로 써서 프로젝터에 표시. 대상 모니터를 골라 바꿀 수 있음 | 줌 엔진과 같은 화면 캡처 구현 필요 |

### 구현 요점

- 모니터는 디스플레이 UUID(`CGDisplayCreateUUIDFromDisplayID`)로 구분해, 다시 연결해도 같은 화면으로 알아봄
- 획 좌표는 화면 크기에 대한 비율(0~1)로 저장해, 해상도가 바뀌거나 다른 화면으로 옮겨도 같은 위치에 그려짐
- Apple Pencil은 태블릿 이벤트(`NSEvent.pressure`)로 들어오며, 손가락 터치는 Sidecar가 제스처로 처리해 판서가 되지 않음(손바닥 오인식 방지). Sidecar 연결과 macOS의 Pencil 더블 탭 사용 설정 후 압력 및 지우개 ↔ 이전 도구 전환을 실기 확인
- 지우개 끝 판별의 장치 종류는 마우스 누름·뗌·드래그·이동과 태블릿 근접 이벤트에서만 읽는다. 진입·이탈 이벤트에서 `NSEvent.pointingDeviceType`을 읽으면 예외가 발생하므로 그 밖의 이벤트는 지우개 끝이 아닌 것으로 다룬다.
- iPad 화면에는 크고 터치하기 쉬운 도구 팔레트를 따로 띄움(색·펜·지우개·실행 취소). Sidecar 사이드바는 꺼두길 안내
- 수업에서는 무선보다 끊김이 적은 **USB 유선 Sidecar**를 권장
- Windows에는 Sidecar가 없으므로, Windows 확장 단계에서는 iPad용 동반 앱(PencilKit)을 만들어 로컬 네트워크로 획을 보내는 방식을 검토. 획을 비율 좌표로 저장하는 지금 구조가 그대로 쓰임

### 모니터 연결 해제 시 대응

원칙은 **판서는 절대 잃지 않고, 진행 중인 기능은 남은 화면으로 옮긴다**입니다. 화면 구성 변경은 `CGDisplayRegisterReconfigurationCallback`으로 감지하고, 이벤트가 연달아 오므로 0.3초 모아서 한 번에 처리합니다.

| 상황 | 대응 |
| --- | --- |
| 그리는 도중 해제 | 그리던 획은 그 자리까지 확정하고 입력 종료 |
| 해제된 화면의 판서 | 기본은 **보관**: UUID별로 메모리와 자동 보관 파일에 저장. 설정에서 "주 화면으로 옮기기"나 "삭제"로 바꿀 수 있음 |
| iPad가 끊김 (판서 패드 사용 중) | 프로젝터 화면의 판서는 그대로 유지, 입력은 마우스·태블릿으로 자동 전환. "iPad 연결 끊김 — 판서는 그대로입니다" 알림 |
| 프로젝터가 끊김 (판서 패드 대상) | 판서 패드의 대상을 남은 주 화면으로 자동 변경 |
| 줌 사용 중 | 해당 화면의 캡처(`SCStream`)를 정리하고 줌 종료. 다른 화면의 줌은 유지 |
| 보드 사용 중 | 보드 페이지는 화면과 무관한 문서로 보관되며, 남은 화면에서 같은 페이지로 이어 쓸 수 있음 |
| 타이머 배지·쉬는 시간 전체 화면 | 남은 화면(우선순위: 프로젝터 → 주 모니터)으로 즉시 이동. 타이머는 시계 기준이라 멈추지 않음 |
| 도구 팔레트 | 화면이 사라지면 주 모니터의 마지막 위치로 이동 |
| 다시 연결됨 | 같은 UUID면 "이전 판서를 복원할까요?" 알림(설정으로 자동 복원 가능). 해상도가 바뀌었으면 비율 좌표로 맞춰 다시 그림 |
| 미러링 켜기/끄기, 해상도 변경 | 오버레이 창을 다시 만들고 판서를 비율 좌표로 다시 배치 |
| 맥 잠자기·뚜껑 닫기 | 연결 해제와 동일하게 보관, 깨어나면 위의 "다시 연결됨" 규칙 적용 |

실행 취소 기록도 화면별로 함께 보관해, 복원한 뒤에도 이어서 되돌릴 수 있게 합니다.

| 번호 | 확정 결정 |
| --- | --- |
| 1 | 프리셋은 **주 화면 · 보조화면1 · 보조화면2**로 구성하고 보조 화면은 비울 수 있다. 각 화면은 순서 있는 모니터 목록이며, 둘 이상이면 서로 미러링하고 첫 모니터가 마스터다. 화면끼리는 확장한다. |
| 2 | 화면 위치는 `x`, `y`가 각각 `-1...1`인 3×3 격자 칸으로 저장한다. 주 화면은 가운데 `(0, 0)`에 고정하고 보조 화면은 서로 다른 칸을 쓴다. `y=-1`은 위, `y=+1`은 아래다. 모든 화면은 변을 맞댄 점유 칸을 통해 주 화면에 이어져야 하며 대각선만 닿는 배치는 저장하지 않는다. 계획할 때는 연결된 화면 중 역할 순서(주 → 보조1 → 보조2)의 첫 화면을 원점 `(0, 0)`의 주 디스플레이로 삼고, 격자 이웃을 너비 우선으로 찾아 먼저 배치된 이웃의 변에 틈 없이 붙인다. 중간 화면이 연결되지 않아 끊긴 화면은 앵커 기준 방향의 배치 묶음 바깥 변에 붙인다. 계획 결과가 겹치면 적용 불가 사유를 표시한다. |
| 3 | 해상도는 프리셋에 저장하지 않고 마스터 모니터의 현재 모드를 사용한다. 모델은 나중에 모니터별 모드를 추가할 수 있게 분리한다. |
| 4 | `autoSwitchEnabled` 기본값은 꺼짐이다. 프리셋의 모니터별 `autoMatch` 집합과 연결 모니터 집합이 1:1로 정확히 같을 때만 해당 프리셋을 자동 전환 대상으로 삼는다. 둘 이상이 일치하면 프리셋 배열에서 가장 앞선 항목이 우선이며 설정에서 순서를 바꿀 수 있다. |
| 5 | 연결 변화 후 집합이 `DisplayPresetDefaults.connectionStabilityInterval`(5초) 동안 바뀌지 않은 뒤 판단한다. 일치 프리셋이 없으면 유지하고, 활성 프리셋 집합이 복구되면 다시 적용한다. 자동 적용 뒤 `automaticApplyCooldown`(30초) 동안 다시 적용하지 않고 자체 적용 알림은 무시한다. 쿨다운 중 생긴 연결 변화는 버리지 않고 쿨다운이 끝난 뒤 판단하며, 앱 시작·자동 전환 스위치를 켤 때는 즉시 판단하지 않고 수동 적용 확인 중에는 판단을 미룬다. |
| 6 | 프리셋 전환으로 사라지는 화면의 판서는 일반 연결 해제 설정과 관계없이 보관한다. |
| 7 | 프리셋은 최대 8개, 이름은 1~40자다. 프리셋 목록·순서·자동 체크와 모니터 식별 필드(`uuid`, `vendor`, `model`, `serial`, `name`, `kind`)는 `.pansetting`에 일반 묶음으로 기본 포함한다. `autoSwitchEnabled`만 이 컴퓨터의 스위치로 남겨 내보내기·가져오기에서 제외한다. 가져온 프리셋의 연결되지 않은 모니터는 칸·목록 순서·자동 체크를 유지한 채 현재 연결 모니터로 다시 지정할 수 있다. |
| 8 | 프리셋 전환 전역 단축키 기본값은 두지 않는다. 사용자가 단축키 설정에서 추가할 수 있고 메뉴바·원형 팔레트에서도 전환한다. |
| 9 | 적용할 때 프리셋 밖의 연결 모니터는 미러링을 풀고 배치된 전체 묶음의 오른쪽 끝에 위를 맞춰 확장한다. 프리셋에 있으나 연결되지 않은 모니터는 건너뛰고 목록으로 알리며 나머지 화면은 적용한다. |

단계 구분

1. **1단계 — 모델·설정·계획**: 데이터 모델, 온라인 모니터 식별·매칭, 실제 구성을 바꾸지 않는 순수 계획 계산, 현재 구성 캡처, 저장·검증·`.pansetting`, 설정 화면 편집과 계획 보기를 구현한다.
2. **2단계 — 수동 적용(구현)**: 직전 구성을 스냅샷으로 보관한 뒤 한 CG 트랜잭션을 `.forAppOnly`로 적용하고, 적용 후 주 화면 가운데의 비모달 확인 패널에서 15초 안에 유지하면 같은 연산을 `.permanently`로 확정한다. 되돌리기·Esc·패널 닫기·시간 만료는 같은 스냅샷 연산을 `.forAppOnly`로 복구한다. 메뉴바·원형 팔레트와 기본값 없는 사용자 지정 전역 단축키 슬롯 8개를 연결하며, 사라지는 화면의 판서는 기존 연결 해제 보관 경로로 강제 보관한다.
3. **3단계 — 자동 전환(구현)**: 연결 집합 안정화, 배열 선두 우선의 1:1 자동 집합 판정, 쿨다운, 자체 화면 변경 알림 무시, 활성 프리셋 복구를 연결한다. 가져온 프리셋은 모니터가 연결되고 저장된 식별과 일치하기 전에는 자동 전환 대상이 되지 않는다. (적용 경로 097, 감시·판정 098)

안전장치 계획: 수동 적용의 확인 대기 중에는 다른 적용을 거부하고, 앱 종료 때도 스냅샷 복구를 시도한다. 확인 전 앱이 종료되면 `.forAppOnly` 구성은 시스템의 세션 또는 영구 구성으로 자동 복구된다. 판서 복원 질문은 확인 패널이 닫힐 때까지 보류한다. 자동 적용은 사용자 확인 창 없이 적용 직후 계획과 실제 구성을 자동 검증하고, 검증 실패 시 직전 구성으로 즉시 복구한다.

## 수업 타이머·쉬는 시간 타이머

두 타이머는 목적이 다릅니다. 수업 타이머는 강사가 보는 작은 시계이고, 쉬는 시간 타이머는 학생 모두가 보는 큰 화면입니다.

| 항목 | 수업 타이머 | 쉬는 시간 타이머 |
| --- | --- | --- |
| 시간 정하는 방식 | 길이 지정(예: 50분) 또는 경과 시간 카운트업 | **종료 시각 지정**(예: 10:50). 지금부터 그 시각까지 남은 시간을 표시 |
| 빠른 설정 | 25·45·50·90분 프리셋 | "+5분 / +10분 / +15분" 버튼으로 종료 시각 자동 계산, 시각 직접 입력도 가능 |
| 표시 | 작은 배지. 드래그 앤 드롭으로 원하는 위치·모니터(iPad 포함)에 배치, 크기·투명도 조절 + 메뉴바 남은 시간 | 전체 화면: 큰 남은 시간(분:초), "10:50에 수업 재개" 문구, 줄어드는 진행 링, 현재 시각 |
| 알림 | 종료 5분 전 배지 색 변경, 종료 시 사운드·깜빡임 | 종료 1분 전 강조 색, 종료 시 사운드 + "수업 재개" 표시 |
| 조작 | 일시정지, 재시작, 리셋 | 종료 시각 변경, 작은 창으로 접기(쉬는 동안 다른 화면 보여주기), 조기 종료 |
| 꾸미기 | 글꼴 크기, 위치 | 배경색·문구·배경 음악(선택), 화면 보호기 스타일 |

### 수업 타이머 배지 배치

강사가 보는 수업 타이머는 드래그 앤 드롭으로 어느 모니터의 어느 위치에든 둘 수 있고, 놓은 자리를 기억합니다.

- **이동**: 배지를 끌어 원하는 위치에 놓음. 모니터 경계를 넘어 끌면 그 모니터(노트북, 프로젝터, Sidecar iPad)로 옮겨짐
- **스냅**: 화면 가장자리·모서리 16px 안에서 놓으면 딱 붙음. `⌥`(Windows `Alt`)를 누른 채 끌면 스냅 없이 자유 배치
- **판서 중에도 이동 가능**: 배지는 판서 오버레이보다 위에 뜨는 별도의 작은 창이라, 배지 위에서 시작한 드래그는 항상 이동으로 처리하고 판서로 처리하지 않음. 배지 밖은 그대로 판서·클릭 통과
- **크기·메뉴**: 모서리를 끌어 크기 조절. 우클릭 메뉴에서 크기(소·중·대), 투명도, 표시 형식(남은 시간/경과 시간), 위치 초기화
- **위치 기억**: 모니터 UUID + 화면 비율 좌표로 저장해, 다음 실행이나 모니터 재연결 때 같은 자리에 나타남. 그 모니터가 없으면 주 모니터의 같은 비율 위치로 옮김
- **학생 화면에서 숨기기**: 기본으로 화면 공유·녹화에서 제외(`NSWindow.sharingType = .none`). 단, 미러링 중인 프로젝터에는 그대로 보이므로 강사 전용 화면(노트북 화면, iPad 확장 화면)에 두는 것을 권장
- **Windows**: 같은 동작을 `WS_EX_TOPMOST` 창으로 구현하고, 공유 제외는 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`

쉬는 시간 타이머는 수업 타이머가 끝났을 때 자동으로 뜨게(예: 수업 종료 → 10분 후 종료되는 쉬는 시간) 연결할 수 있습니다. 남은 시간은 항상 시스템 시계 기준으로 계산해, 맥이 잠시 잠자기에 들어갔다 와도 종료 시각이 어긋나지 않게 합니다. 종료 시각이 지금보다 이르면 "오늘 시각이 지났습니다" 경고를 띄웁니다.

### 쉬는 시간 음악 (유튜브 뮤직 연동)

쉬는 시간이 시작되면 앱이 미리 정한 유튜브 뮤직 재생목록을 **크롬으로 열고**, 끝나면 음악을 멈춥니다. 재생은 크롬에 로그인된 계정으로 하므로, 그 계정이 YouTube Premium(또는 Music Premium)이면 광고 없이 재생됩니다.

1. **설정**: 재생목록 주소(music.youtube.com 링크)를 최대 5개 등록하고 기본값을 지정. 열 브라우저는 크롬(기본) / 크롬에 설치한 YouTube Music 앱 / 기본 브라우저 중 선택
2. **시작**: 쉬는 시간 타이머 시작 시 재생목록을 크롬으로 열고(`open -a "Google Chrome" <URL>`), 타이머 전체 화면을 다시 앞으로 가져옴. 타이머 화면에 음악 켜기/끄기, 다른 재생목록 선택 버튼
3. **페이드아웃**: 종료 60초 전부터 맥 시스템 볼륨을 서서히 낮춤(설정에서 끄기·시간 조절)
4. **종료**: 앱이 열었던 크롬 탭을 닫아 음악을 멈추고, 시스템 볼륨을 원래 값으로 복구한 뒤 "수업 재개" 화면 표시
5. **조기 종료·종료 시각 변경**: 조기 종료하면 즉시 4번 수행, 종료 시각을 바꾸면 페이드아웃 시점도 따라서 이동

구현 요점

- **탭 닫기(macOS)**: AppleScript로 크롬에서 앱이 열었던 주소의 탭만 찾아 닫음. 처음 한 번 **자동화(Apple Events) 권한** 허용이 필요. 권한이 없으면 미디어 키(일시정지)를 보내는 방식으로 대체
- **Windows**: `chrome.exe` 로 주소를 열고(없으면 `ShellExecute`), 종료 시 Windows 미디어 컨트롤(SMTC)로 Chrome 재생만 일시정지(탭은 닫지 않음; 토글인 미디어 키는 이미 멈춘 음악을 다시 틀 수 있어 쓰지 않음). 볼륨은 시스템 전체를 Core Audio(`IAudioEndpointVolume`)로 페이드
- **예외 처리**: 크롬이 없으면 기본 브라우저로 열기. 다른 앱이 소리를 내는 중이면 미디어 키가 엉뚱한 앱을 멈출 수 있어, 가능하면 탭 닫기를 우선 사용
- **하지 않는 것**: 크롬 로그인 정보(쿠키) 읽기, 앱 내부 웹 화면에서 구글 로그인, 광고 차단. 보안과 유튜브 약관 때문
- Premium이 아닌 계정이면 광고가 나올 수 있다고 설정 화면에 안내

### 쉬는 시간 음악 — 로컬 폴더 (2026-10-31 추가)

위 유튜브 뮤직 연동과 **같은 자리에서 소스만 고른다.** 설정 `timer.musicSource` = `youtube`(기본) / `folder`. 재생 시점은 쉬는 시간뿐이며(시작 시 재생, 종료·조기 종료 시 정지), 음원은 앱에 포함하지 않고 사용자가 지정한 폴더만 쓴다. macOS·Windows 동일 동작.

| 설정 키 (`timer`) | 값 | 기본 |
| --- | --- | --- |
| `musicSource` | `"youtube"` \| `"folder"` | `"youtube"` |
| `musicFolderPath` | 문자열(빈 문자열 = 미지정), 제어문자 불가 | `""` |
| `musicOrder` | `"name"`(이름순) \| `"shuffle"`(무작위) | `"name"` |
| `musicRepeat` | `"all"`(전체 반복) \| `"one"`(한 곡 반복) | `"all"` |

- **호환**: 위 4개는 추가 필드다. 파일에 없으면 기본값으로 읽고, 모르는 키는 무시한다(구버전이 새 파일을 읽어도 깨지지 않음). `formatVersion` 은 올리지 않는다. 기존 `musicEnabled`·`fadeEnabled`·`fadeDuration` 은 소스와 무관하게 그대로 적용.
- **곡 수집**: 지정 폴더와 하위 폴더(깊이 3)의 `mp3 m4a aac wav flac`(대소문자 무시). 숨김 파일·폴더 제외, 최대 500곡. 시작 시점에 한 번 스캔한다.
- **순서**: `name` = 폴더 상대경로 기준 대소문자 무시·숫자 인식 정렬. `shuffle` = 시작 때 한 번 섞고, 한 바퀴가 끝나 다시 섞을 때 직전 곡이 맨 앞에 오지 않게 한다.
- **반복**: `all` = 마지막 곡 다음에 처음(무작위면 다시 섞음)으로. `one` = 현재 곡만 반복(타이머 화면의 "다음 곡"으로 넘길 수 있음).
- **재생**: 앱이 직접 재생한다(macOS `AVAudioPlayer`, Windows `Windows.Media.Playback.MediaPlayer`). 곡이 끝나면 다음 곡을 이어서 재생. 재생 실패 곡은 건너뛰고, 한 바퀴 전부 실패하면 멈추고 알린다(무한 반복 금지).
- **페이드**: 종료 시각 기준 `BreakMusicFade` 곡선(기존 코드)으로 **플레이어 자체 볼륨**을 낮춘다. 시스템 볼륨은 건드리지 않는다(캡처·복구 불필요). 종료 시각 변경·조기 종료는 기존 규칙 그대로.
- **타이머 화면**: 켜기/끄기 버튼은 그대로, "다른 재생목록 선택" 자리에 **"다음 곡"** 버튼. 폴더가 비었거나 곡이 없으면 재생하지 않고 화면에 "재생할 음악 파일이 없습니다"를 짧게 표시.
- **설정 화면**: 소스 선택 → `folder` 이면 폴더 경로 표시 + "폴더 선택…" + 순서·반복 선택 + "곡 N개"(경로가 없거나 읽을 수 없으면 "폴더를 찾을 수 없습니다"). 유튜브 소스일 때 기존 항목은 그대로.
- **내보내기·가져오기**: 위 필드는 타이머 묶음에 포함. 다른 PC 의 경로는 그대로 가져오되 없으면 "폴더를 찾을 수 없습니다"로 표시(자동 수정 없음).
- **경로 보안(Windows)**: `musicFolderPath` 는 앞뒤 공백 제거 후 첫 두 글자가 모두 구분자(`\`·`/`)이거나 `\??\` 로 시작하면 거부한다(UNC·장치 경로). 가져온 설정 파일의 `\\서버\공유` 로 쉬는 시간 자동 스캔이 SMB 접속해 인증 정보가 넘어가는 것을 막는다. 단일 `/` 시작(macOS 경로)은 허용 — 내보내기 호환. 설정 화면에서 네트워크 폴더를 고르면 안내 후 반영하지 않는다.
- **하지 않는 것**: 음원 번들, 태그·앨범아트 표시, 재생목록 편집, 수업 중 재생, 스트리밍·웹 등록 외 다운로드.

## 단축키

다른 앱의 단축키를 빼앗는 전역 단축키는 **8개**로 줄이고, 모두 **앱 수정키 + 기능 영문 첫 글자**로 통일합니다. 앱 수정키는 macOS `⌃⌥`(Control+Option), Windows `Ctrl+Alt`로, 두 OS에서 같은 글자가 같은 기능을 합니다. 나머지는 판서 모드 안에서만 동작하는 한 글자 키입니다.

### 설계 원칙

1. **전역은 최소로**: 충돌은 전역 단축키에서만 생깁니다. 도구 전환은 판서 모드 안으로 모두 옮깁니다.
2. **글자 = 기능 이름**: P=Pen, Z=Zoom, L=Laser, S=Spotlight, M=Minutes(수업), B=Break(쉬는 시간), E=Erase all(전체 지우기).
3. **전역과 판서 모드의 글자를 맞춤**: `⌃⌥L`로 켜면 레이저, 판서 모드 안에서도 `L`이 레이저입니다.
4. **익숙한 관례를 따름**: 도구 키는 Photoshop·Figma(P 펜, E 지우개, V 선택, T 텍스트, R 사각형, O 원, `[` `]` 크기), 화이트·블랙보드는 PowerPoint 슬라이드쇼의 W(흰 화면)·B(검은 화면)와 같게.
5. **한글 입력 상태에서도 동작**: 글자가 아니라 물리 키 위치(macOS keyCode, Windows 가상 키코드)로 인식해, 한글 상태에서 P를 눌러도 ㅔ가 아니라 펜이 됩니다. 텍스트 입력 중에는 한 글자 단축키를 꺼둡니다.
6. **OS 간 1:1 대응**: `⌘`↔`Ctrl`, `⌥`↔`Alt`, `⌫`↔`Backspace`. 설정은 OS와 무관한 형식(예: `AppMod+P`)으로 저장해 Windows 버전과 설정 파일을 공유합니다.

기본 키가 없는 기능도 설정 → 단축키에 "없음"으로 표시하며, 사용자가 해당 기능의 전역·판서·줌 범위에 맞는 키를 직접 지정하거나 해제할 수 있습니다. 전역 범위는 앱 수정키 조합만 받고, 판서·줌 범위는 앱 수정키 조합을 받지 않습니다.

### 남은 충돌 가능성과 대응

- **VoiceOver(macOS)**: 켜져 있으면 `⌃⌥`가 VoiceOver 키입니다. 감지되면 앱 수정키를 `⌃⌥⇧`로 바꾸도록 안내합니다.
- **AltGr 키보드(Windows)**: 독일어·폴란드어 등 배열에서는 `Ctrl+Alt`가 특수문자 입력입니다. 이 배열이 감지되면 `Ctrl+Alt+Shift`로 자동 전환합니다. 한국어·영어 배열은 해당 없습니다.
- **앱 자체 단축키**: Word의 `Ctrl+Alt+M`(메모 삽입)처럼 일부 앱의 단축키는 앱이 실행 중일 때 가려집니다. 수업 중 영향은 작지만 설정에서 바꿀 수 있습니다.
- **등록 실패 감지**: Windows는 `RegisterHotKey`가 실패하면 이미 다른 앱이 쓰는 키이므로 즉시 알립니다. macOS는 등록 실패가 항상 감지되지 않아, 알려진 충돌 목록(위 표)과 비교해 경고하고 다른 키를 제안합니다.

## 도움말 화면

`?` 키를 누르면 화면 위에 도움말이 겹쳐 뜨고, 기능을 아이콘과 이름으로 보여주며 각 기능 옆에 단축키를 표시합니다. `?`는 웹·디자인 도구(Gmail, GitHub, Figma 등)에서 널리 쓰는 도움말 키입니다.

(원문 임베드: 도움말 화면 목업 · 판서 모드에서 연 경우)

### 여는 방법

| 상황 | macOS | Windows |
| --- | --- | --- |
| 어느 앱을 쓰든 (전역) | `⌃⌥/` (`?` 키 위치) | `Ctrl+Alt+/` |
| 판서·줌·보드 모드 안 | `?` | `?` 또는 `F1` |
| 마우스로 | 메뉴바 아이콘 → 도움말, 도구 팔레트의 `?` 버튼 | 작업 표시줄 아이콘 → 도움말 |

- **누르고 있기**: 누르는 동안만 보이고 떼면 사라짐. 수업 중 키를 잠깐 확인할 때
- **짧게 누르기**: 화면에 고정. 다시 `?`나 `Esc`, 바깥 클릭으로 닫기

### 화면 구성

- **지금 모드에 맞춘 내용**: 판서 모드면 도구·편집, 줌 모드면 배율·미리보기, 보드면 페이지 키를 먼저 보여주고, 나머지는 아래쪽에 표시. 제목에 현재 모드 표시
- **기능별 카드**: 도구 / 편집 / 화면·보드·줌 / 타이머·기타 4개 묶음. 항목마다 아이콘 → 이름 → 오른쪽 끝에 키캡 모양 단축키
- **아이콘**: 도구 팔레트와 같은 아이콘을 써서 두 화면이 연결되게. 디자인 세트(`assets/icons/<키>.svg`)를 macOS·Windows 가 함께 쓰고, 디자인이 없는 키만 macOS 는 SF Symbols, Windows 는 Segoe Fluent 글리프로 대체([`icons.md`](icons.md))
- **현재 상태 강조**: 지금 쓰는 도구는 강조색, 지우개는 현재 방식(부분/획/영역), 줌은 현재 배율을 함께 표시
- **OS에 맞는 표기**: 같은 설정을 macOS는 `⌃⌥Z`, Windows는 `Ctrl+Alt+Z`로 표시
- **사용자 설정 반영**: 설정에서 바꾼 단축키를 그대로 표시. 다른 앱과 충돌 경고가 있는 키는 ⚠ 표시
- **찾기**: 고정 표시 상태에서 글자를 치면 기능 이름(한글)이나 키로 바로 걸러줌. 이때 한 글자 단축키는 잠시 꺼짐

### 동작

- 항목을 클릭하면 그 기능이 바로 실행되고 도움말은 닫힘
- 누르고 있기 상태에서 다른 단축키를 누르면 해당 항목이 깜빡여 어느 키인지 바로 확인
- 배경은 반투명 어둑게 + 흐림 처리해 뒤 화면이 어느 정도 보이게. 판서 내용은 영향 없음
- 마우스가 있는 모니터(iPad 포함)에 표시. 화면 공유·녹화에서는 기본으로 제외(학생에게 보여주려면 설정에서 켬)
- 처음 실행할 때 한 번 자동으로 열어 주요 키를 안내
- 구현: 도움말 내용은 단축키 설정 파일에서 자동 생성해, 기능이 추가되거나 키가 바뀌어도 도움말을 따로 고칠 필요가 없게 함. Windows도 같은 데이터를 사용

## 기술 구조

입력은 모두 하나의 상태 관리자(AppState)를 거치고, 기능별 엔진이 결과를 오버레이 창과 타이머 화면에 그립니다. 엔진을 나눠 두면 로드맵 단계별로 독립적으로 개발·테스트할 수 있습니다.

(원문 임베드: 앱 구조 · 입력 3종, 엔진 4개, 출력 2종)

| 모듈 | 핵심 구현 |
| --- | --- |
| 오버레이 창 | 모니터마다 테두리 없는 투명 `NSPanel`. `AppWindowLevel`의 계층을 사용하고, `canJoinAllSpaces` + `fullScreenAuxiliary`로 전체화면 앱 위에도 표시. 일반 모드와 통과 모드에서 `ignoresMouseEvents = true` |
| 판서 엔진 | 획 = 점 배열(위치·압력·시간). 완성된 획은 비트맵에 굽고 그리는 중인 획만 `CAShapeLayer`로 그려 지연 최소화. Undo는 명령 스택 |
| 지우개 엔진 | 획마다 경계 사각형을 보관해 지우개 원과 빠르게 교차 판정. 부분 지우기는 원 안의 점을 잘라 획을 나눔, 획 단위는 획 전체 삭제, 영역은 다각형 포함 검사 |
| 줌 엔진 | `SCStream`으로 현재 모니터를 60fps 캡처, 오버레이 창은 캡처에서 제외. IOSurface를 레이어에 직접 전달하고 없을 때만 경고 후 CGImage 변환. 확대 중심은 마우스 위치를 보간(lerp)해 부드럽게 이동. 정지 줌은 한 프레임만 사용 |
| 타이머 엔진 | 종료 시각(`Date`)을 저장하고 남은 시간 = 종료 시각 − 현재 시각으로 매번 계산. 잠자기 복귀 알림에서 다시 계산 |
| 단축키 | 전역: Carbon `RegisterEventHotKey` 직접 사용. 판서 모드 단축키는 오버레이 창의 `keyDown` |
| 설정 저장 | `UserDefaults`(설정), 판서·보드는 JSON 파일로 자동 보관 |

| 창 계층 | `AppWindowLevel` | `NSWindow.Level` | 대상 |
| --- | --- | --- | --- |
| 오버레이 | `overlay` | `.screenSaver` | 판서 오버레이 |
| 효과 | `effect` | `.screenSaver + 1` | 줌·스포트라이트 |
| 도구 | `tool` | `.screenSaver + 2` | 팔레트·수업 배지 |

### 도구별 마지막 설정

색과 크기를 쓰는 도구는 아래처럼 서로 독립된 마지막 사용값을 `tools.perToolMemory`에 저장합니다. 도구 전환 경로와 무관하게 현재 도구의 슬롯을 읽으며, 색 번호키와 크기 조절은 그 슬롯만 갱신합니다. 레이저에서 색 번호키를 누르면 같은 프리셋을 레이저 색으로 설정하고, 지우개·선택·가리개에서는 상태를 바꾸지 않습니다.

| 도구 | 기억 필드 | 값 |
| --- | --- | --- |
| 펜 | `pen` | 색 프리셋 인덱스, 굵기 |
| 형광펜 | `highlighter` | 색 프리셋 인덱스, 굵기 |
| 화살표 | `arrow` | 색 프리셋 인덱스, 굵기 |
| 사각형 | `rectangle` | 색 프리셋 인덱스, 굵기 |
| 원 | `ellipse` | 색 프리셋 인덱스, 굵기 |
| 텍스트 | `text` | 색 프리셋 인덱스, 글자 크기 |

도구 묶음 스키마는 굵기와 글자 크기를 `perToolMemory`에만 기록합니다. 옛 `penWidth`·`highlighterWidth`·`textFontSize` 키는 `perToolMemory`가 없는 설정을 이행할 때만 읽고 다시 쓰지 않습니다. 이행 시 색은 첫 프리셋, 펜·화살표·사각형·원 굵기는 옛 `penWidth`, 형광펜 굵기는 옛 `highlighterWidth`, 텍스트 크기는 옛 `textFontSize`에서 시작하며, 옛 키도 없으면 같은 기본값을 사용합니다. 따라서 업그레이드 직후 모습과 동작은 이전 버전과 같습니다. 색 프리셋 수가 줄면 각 슬롯의 인덱스는 마지막 프리셋 인덱스로 클램프합니다. 레이저와 지우개 설정은 기존 필드를 그대로 사용합니다.

### 설정 내보내기·가져오기

모든 설정을 파일 하나로 내보내고, 다른 맥이나 Windows PC에서 그대로 가져올 수 있습니다. 새 컴퓨터로 옮길 때, 강사끼리 설정을 나눌 때, 학교·기관에서 표준 설정을 배포할 때 씁니다.

- **위치**: 설정 → 일반 탭의 [내보내기…] [가져오기…] [기본값으로 초기화] 버튼, 메뉴바 메뉴에도 같은 항목
- **파일 형식**: 확장자 `.pansetting`의 JSON 파일(사람이 읽을 수 있는 텍스트). 맨 앞에 형식 버전·앱 버전·만든 OS를 기록. 파일을 더블클릭하면 앱이 열리며 가져오기 화면이 뜨게 확장자 등록
- **항목 선택**: 내보낼 때와 가져올 때 모두 묶음별로 고를 수 있음 — 도구(색·굵기·투명도), 지우개, 줌, 보드, 타이머(프리셋·쉬는 시간 문구·음악 재생목록), 화면 구성, 단축키, 도움말·일반
- **단축키는 OS 공용**: `AppMod+P`처럼 OS와 무관한 형식으로 저장하므로, 맥에서 내보낸 파일을 Windows에서 가져오면 `Ctrl+Alt+P`로 자동 적용
- **화면 구성 이동**: 프리셋과 모니터 식별 정보는 기본 포함하지만 이 컴퓨터의 `autoSwitchEnabled` 값은 파일에 넣지 않는다. 가져오기 미리보기는 바뀌는 경우에만 "프리셋 N개 추가/교체"로 표시한다.
- **이 컴퓨터 전용 항목은 기본 제외**: 모니터별 타이머·팔레트 위치, 자동 보관 폴더 경로처럼 컴퓨터마다 다른 값은 따로 체크해야 포함
- **포함하지 않는 것**: 판서·보드 내용(저장·내보내기 기능으로 따로), OS 권한 허용 상태, 로그인 정보. 재생목록 주소가 들어간다면 내보내기 화면에서 알려줌

가져오기 순서

1. 파일 검사: 형식·버전 확인, 값 범위 검사(예: 줌 1.25~8배). 알 수 없는 항목은 무시하고, 이전 버전 파일은 새 형식으로 자동 변환
2. 미리보기: 바뀌는 항목만 "현재 → 가져올 값"으로 보여주고 묶음별로 선택
3. 단축키 충돌 검사: 이 컴퓨터에서 등록이 안 되거나 알려진 충돌에 걸리는 키는 ⚠ 표시와 대안 제안
4. 적용 전 현재 설정을 자동 백업하고, 적용 후 "이전 설정으로 되돌리기" 버튼 제공(최근 백업 5개 보관)
