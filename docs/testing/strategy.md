# EduTools 시험 전략

## 목적과 원칙

시험은 앱 빌드와 분리된 SwiftPM 패키지에서 가장 낮은 신뢰 가능한 계층으로 실행한다. 순수 로직은 헤드리스에서 빠르게 검증하고, WindowServer·권한·하드웨어가 필요한 동작은 해당 환경에서만 판정한다. 실패를 skip·재시도·고정 대기로 숨기지 않으며, UNRUNNABLE은 통과나 실패와 구분한다.

## 계층

| 계층 | 검증 | 환경·실행자 | 현재 진입점 |
| --- | --- | --- | --- |
| T0 빌드 | arm64·x86_64 컴파일, 번들·서명·리소스 | 모든 맥, 개발자 | `./build.sh` |
| T1 단위 | 입력→출력 순수 로직 | 헤드리스, 개발자 | `scripts/test.sh unit` |
| T2 통합 | 모듈 합성, 임시 I/O, 설정·골든, 가짜 계층 | 헤드리스, 개발자 | `scripts/test.sh integration` |
| T3 GUI | 실제 뷰·창과 합성 이벤트 | WindowServer, 사용자 맥 | 예정(S3) |
| T4 E2E | 실제 앱·OS 입력·AX·화면 픽셀 | 접근성·화면 기록 권한, 사용자 | 예정(S4) |
| T5 릴리스 | 번들·서명·plist·리소스 개수·속성 레이어 정합·자체 시험 코드 탐지·DMG | 모든 맥, 릴리스 담당 | [`scripts/verify-bundle.sh`](../../scripts/verify-bundle.sh) |
| T6 수동 | Pencil·Sidecar·다중 모니터·프로젝터·권한 | 실제 장비, 사용자 | [`manual-checklist.md`](manual-checklist.md) |

횡단 장치는 교차 플랫폼 JSON 픽스처, 버전별 골든 설정, 시드 고정 불변식, 변이 증거, 크래시 회귀 대장, 정보용 커버리지 지도다.

## 위험 인벤토리

| 영역 | 주된 위험 | 필수 계층 |
| --- | --- | --- |
| 단축키·카탈로그·override·충돌 | 입력 동치와 명령 단절 | T1, 설정 합성 T2, 실제 핫키 T4 |
| 설정·백업·구버전 호환 | 데이터 유실 | T1 + 버전별 골든 T2 |
| 판서·지우개·도형·undo | 수업 자료 손상 | T1, 입력 파이프라인 T3 |
| 줌 기하·좌표 변환 | 포인터와 판서 위치 오차 | T1, 실제 포인터 T3 |
| 화면 프리셋·적용 상태 기계 | 잘못된 하드웨어 구성·복구 실패 | 플래너 T1, 가짜 CG 계층 T2, 실제 적용 T6 |
| 보관·복원·내보내기 | 파일 유실·잘못된 이미지 | T2 |
| 타이머·음악 URL | 시간 오차·안전하지 않은 URL | T1 |
| 창·팔레트·입력 소유권 | 입력 유실·잘못된 창 계층 | T3 + 핵심 스모크 T4 |

## 개발 게이트와 역할

| 변경 | 필수 게이트 |
| --- | --- |
| 순수 로직 | T1, 필요하면 픽스처·시드 불변식 |
| 설정 스키마 | T1 + 구버전 골든 왕복 T2 |
| 단축키 카탈로그 | T1 + 교차 플랫폼 픽스처, 권장 T4 |
| 입력·뷰·줌·팔레트 | T3, 권장 T4·T6 |
| 디스플레이·하드웨어 | 플래너 T1 + 가짜 계층 T2 + 실제 장비 T6 |
| 크래시·데이터 유실 수정 | 가능한 가장 낮은 재현 시험 + 회귀 대장 |

모든 변경의 G1은 `scripts/test.sh unit integration`이며 종료코드 0과 실패 0이 필요하다. `./build.sh test`는 T0 앱 빌드·잔여 SelfTest·G1을 묶는다. 입력·뷰 변경의 G2는 사용자 WindowServer에서 T3를 실행한다. 릴리스 G3는 G1·G2에 T4 스모크, T5, T6 기록을 더한다. 개발자는 헤드리스 G1과 변이 증거를 책임지고, 사용자는 권한·화면·실장비가 필요한 G2/G3를 확인한다.

## 정책과 단계

- 위험 근거 없는 시험, 같은 동작의 사례 나열, 소스 문구 고정 시험, 기존 시험 약화·삭제·skip은 금지한다.
- 결정론을 위해 시계·난수·경로를 주입하고 정렬을 고정한다. 플레이키 실패는 재시도로 덮지 않는다.
- 골든 갱신은 명시적 갱신 모드와 diff 검수를 거친다. 커버리지는 게이트가 아니라 영향 영역의 빈 곳을 찾는 지도다.
- S1은 SwiftPM·지원 도구·단축키/줌/기하 이관, S1b/c는 나머지 SelfTest 이관, S2는 통합 이음새, S3는 GUI, S4는 E2E, S6는 문서 동기화다. S5의 릴리스 검증·수동 체크리스트·크래시 대장은 완료했고, CI(GitHub Actions)는 러너의 macOS 26 지원 여부를 확인한 뒤 제안하므로 미정이다.
- [`manual-checklist.md`](manual-checklist.md)는 실제 장비·권한·사용자 흐름의 수동 판정 절차를 담고, [`crash-regressions.md`](crash-regressions.md)는 크래시의 증상·원인·수정·재현 시험을 추적한다. `e2e.md`만 예정(S4)이다.
- 앱 번들에는 자체 시험 코드가 아직 포함되어 있다. S1b/c에서 제거할 예정이며, [`scripts/verify-bundle.sh`](../../scripts/verify-bundle.sh)는 현재 이를 INFO로 표시하고 이관 완료 후 FAIL로 승격한다.
